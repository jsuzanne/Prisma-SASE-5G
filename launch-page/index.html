GUIDE EXPLICATIF DES BRIQUES TECHNIQUES DU LAB

1. 5G Orchestrator

ROLE=core (:8080)

Cerveau d'orchestration hébergé sur la VM Core (exposé via 5gorchestrator.stigix.io). Il unifie en une seule interface Web et API REST la création des cartes SIM dans le cœur 5G, le pilotage à distance des modems radio et l'enregistrement des identités/sessions dans Prisma SASE 5G.

FastAPI / Python State Reconciler Live API Inspector 1-Click Demo Packs

2. VM 5G Core (Open5GS)

Packet Core + Mongo

Cœur de réseau mobile 5G Standalone (3GPP Release 17). La base MongoDB stocke les abonnés (IMSI, clés K/OPc, QoS 5QI, débit AMBR). L'AMF gère l'attachement radio (N1/N2), le SMF alloue les IP de session PDU (10.45.0.x) et l'UPF achemine les paquets utilisateur (N3/N6).

Open5GS v2.7+ MongoDB :27017 SMF/AMF Metrics :9090 GTP-U N3 :2152

3. VM 5G RAN (UERANSIM)

ROLE=ue-agent (:8081)

Simulateur d'accès radio 5G hébergeant la station de base nr-gnb et le micro-service RAN Agent. À chaque demande de l'Orchestrator, l'agent génère le fichier YAML du terminal, lance un processus nr-ue supervisé et monte une interface réseau dédiée (uesimtun0, uesimtun1…).

UERANSIM nr-gnb / nr-ue SCTP N2 :38412 Linux TUN uesimtun* Per-UE Ping & Exec

4. Prisma SASE 5G (SCM)

Zero-Trust Cloud

Solution cloud Palo Alto Networks gérée depuis Strata Cloud Manager. Permet d'appliquer des politiques de sécurité Zero-Trust granulaires basées sur l'identité matérielle et SIM (IMSI, IMEI, APN, Groupe d'abonnés) sans aucun agent logiciel requis sur les objets connectés (IoT/OT).

OAuth2 TSG API /tenantUEInfo /uesession/register Permissive vs Restrictive

5. Stigix 5G Lab

Traffic & Threat Lab

Accessible sur stigix5glab.stigix.io, cette instance Stigix génère du trafic applicatif continu et des scénarios d'attaque (EICAR, C2, DNS Tunneling, URL Filtering, DLP) à travers l'infrastructure 5G afin de peupler les tableaux de bord SCM et prouver l'efficacité des règles de sécurité en direct.

SaaS & IoT Generators Web Wireshark Stateful PCAP Replay Threat & C2 Audit

6. Cloudflare Zero-Trust Edge

Cloudflare Pages & Tunnels

Expose de manière sécurisée en HTTPS les interfaces de contrôle du lab (5gorchestrator.stigix.io et stigix5glab.stigix.io) via des tunnels sortants chiffrés cloudflared, sans ouvrir aucun port entrant public (MongoDB 27017 et Open5GS 9090 restent isolés en loopback local).

ARCHITECTURE BLUEPRINT

Topologie Bi-VM : 5G RAN ⇄ 5G Core ⇄ Prisma SASE 5G

Le lab repose sur une séparation réaliste entre le plan d'accès radio (VM UERANSIM), le cœur de réseau paquet (VM Open5GS) et le cloud de sécurité Palo Alto Networks Prisma SASE 5G :

  • Plan de Contrôle Radio (Interface N2 — SCTP Port 38412) Le démon nr-gnb (VM RAN) établit l'association NGAP/SCTP vers l'AMF Open5GS (VM Core) pour gérer l'enregistrement NAS et l'authentification mutuelle AKA de chaque carte SIM (nr-ue).
  • Plan Utilisateur Mobile (Interface N3 — GTP-U UDP Port 2152) Dès que le SMF valide la session PDU, un tunnel GTP-U encapsule le trafic IP de l'interface uesimtunX (VM RAN) jusqu'à l'UPF (VM Core).
  • Interconnexion SASE (Interface N6 + API REST OAuth2) Le trafic dé-encapsulé par l'UPF est routé vers Prisma SASE 5G tandis que l'Orchestrator notifie Strata Cloud Manager de l'association (IPv4, IMSI, IMEI, APN) pour appliquer les règles de pare-feu L7 Zero-Trust.
AUTOMATED CALL FLOW

Cycle de Vie Automatisé d'un Terminal 5G en 7 Étapes

  • Étape 1 · Génération 3GPP : Calcul d'un IMSI unique, d'un IMEI valide (TAC constructeur + Luhn) et des clés K/OPc.
  • Étape 2 · Provisionnement Core (MongoDB) : Insertion de l'abonné dans open5gs.subscribers avec son APN/DNN et sa Slice SST/SD.
  • Étape 3 · Provisionnement Identité Prisma SASE 5G : Appel POST /mt/manage/5g/tenantUEInfo vers Strata Cloud Manager et affectation au groupe de sécurité métier.
  • Étape 4 · Instanciation Radio UERANSIM : L'agent RAN génère ue-<imsi>.yaml et lance le démon nr-ue.
  • Étape 5 · Attachement PDU & Allocation IP : Le terminal s'attache au gNB, l'AMF/SMF alloue une IPv4 (10.45.0.X) sur uesimtunX.
  • Étape 6 · Corrélation IP Temps Réel : Le moteur de synchronisation détecte l'IP active dans le SMF et appelle POST /uesession/register dans SCM.
  • Étape 7 · Injection de Trafic & Inspection : Les flux lancés depuis uesimtunX ou Stigix 5G Lab sont inspectés sous l'identité 5G du terminal.
REAL-TIME RECONCILIATION ENGINE

Réconciliateur Ground-Truth à 4 Sources

Contrairement aux simulateurs statiques, le 5G Orchestrator n'invente jamais l'état d'une SIM : il réconcilie en continu 4 sources de vérité indépendantes toutes les quelques secondes :

  • Source 1 · Strata Cloud Manager (Prisma SASE 5G) : Inventaire des identités SIM/IMEI déclarées et des groupes de politiques associés.
  • Source 2 · Open5GS MongoDB : Liste des abonnés provisionnés dans la base locale du cœur 5G.
  • Source 3 · Open5GS SMF & AMF Telemetry : État réel des sessions PDU actives en mémoire et adresses IPv4 allouées.
  • Source 4 · UERANSIM RAN Agent : Processus Linux nr-ue réellement en cours d'exécution et interfaces réseau uesimtun* présentes sur la VM Radio.
